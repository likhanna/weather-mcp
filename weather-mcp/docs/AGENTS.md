# Правила для AI-агента

Эти правила относятся к работе с проектом `weather-mcp`. Учитывайте также корневой `Agent.md` и инструкции в корневом `AGENTS.md`.

## Область изменений

- Изменяйте только файлы, необходимые для явно поставленной задачи. Для документации используйте `docs/`; не переписывайте исходники ради удобства описания.
- Исходники в `src/`, тесты в `test/`, конфигурацию, зависимости и Docker-файлы меняйте только тогда, когда этого требует задача.
- Не добавляйте секреты, реальные ключи API, пользовательские координаты или персональные данные.
- Не меняйте lock-файл и не добавляйте зависимость, если это не требуется реализацией.

## Контракты, которые нельзя ломать

- MCP-сервер использует STDIO: stdout зарезервирован для протокола MCP/JSON-RPC, диагностические сообщения направляются в stderr.
- Сохраняйте имена зарегистрированных инструментов и их входные схемы: `get_weather`, `assess_weather_risk`, `find_safe_weather_window`, `compare_weather_windows`.
- Не меняйте без отдельного согласования структуру успешных ответов, семантику ошибок и правил выбора/сравнения окон.
- Входное время для оценки и поиска интерпретируется как московское время в формате `YYYY-MM-DDTHH:mm`; ограничения диапазона прогноза и длительностей являются частью поведения.
- Источник прогноза и геокодирования — Open-Meteo; API-ключ не требуется.

## Проверки

- После изменений исходного кода запускайте `npm run ci` из каталога `weather-mcp` (сборка TypeScript и все тесты).
- Для изменений документации проверьте соответствие имен, схем и команд исходникам и `package.json`; не заявляйте о проверках, которые фактически не запускались.
- При изменении Docker-файлов дополнительно соберите образ, если Docker доступен; если нет — укажите, что сборка не проверена.

## Когда спросить пользователя

Уточните требования до продолжения, если не хватает обязательного поведения или критериев, требования противоречат друг другу, либо изменение затрагивает публичный контракт/API, архитектуру, миграцию или внешнюю систему. Для таких действий следуйте подтверждениям и контрольным точкам из корневого `Agent.md`. Не задавайте вопрос, если решение прямо следует из задачи и безопасно ограничено её областью.

## Критерии готовности

- Изменены только относящиеся к задаче файлы, а документация описывает подтверждённое поведение.
- Обязательные проверки реально выполнены и их результат сообщён; непроверенные проверки явно обозначены.
- Публичные контракты сохранены либо их изменение отдельно согласовано.
- Итог содержит краткое описание изменений, созданные файлы, проверки и оставшиеся ограничения.
