# Контекст проекта

## Что реализовано

- TypeScript MCP-сервер `weather-mcp`, работающий через STDIO.
- `get_weather`: текущие условия и дневной прогноз на 1–7 дней.
- `assess_weather_risk`: оценка почасового прогноза для наружных работ с уровнями `LOW`, `MEDIUM`, `HIGH` и рекомендациями `PROCEED`, `REVIEW`, `CANCEL`.
- `find_safe_weather_window`: перебор почасовых кандидатов в интервале и ранжирование по уровню риска, числу факторов и времени начала.
- `compare_weather_windows`: оценка двух окон с выбором меньшего уровня риска или сообщением о равенстве.
- Проверка доступности через `GET /health` на loopback при заданном `HEALTH_PORT`; в Docker также предусмотрен health check.
- Тесты на инструменты, оценку риска, время, кэш и health endpoint.

## Архитектурные решения

- Сервер и инструменты собраны в `src/index.ts`; погодный клиент и расчёты риска находятся в `src/open-meteo.ts` и `src/risk.ts`, временная логика — в `src/time.ts`.
- Для геокодирования и погоды используется внешний Open-Meteo API без API-ключа. Неоднозначный город требует уточнения, автоматический выбор не делается.
- Время запросов на работы задаётся по Москве. Проверяется актуальность начала и попадание конца работ в горизонт прогноза до пяти суток.
- Повторные ответы `get_weather` кэшируются в памяти процесса; поиск безопасных окон получает свежий прогноз. Данные запросов не сохраняются на диск.
- HTTP health endpoint включается только при заданном `HEALTH_PORT`; сам MCP-транспорт остаётся на STDIO.
- Риск определяется фиксированными порогами осадков, ветра и температуры. Наивысший обнаруженный уровень задаёт итоговую рекомендацию.

## Известные ограничения и проблемы

- Результаты зависят от доступности, полноты и горизонта прогноза Open-Meteo; сетевые запросы ограничены тайм-аутом.
- Оценка относится к прогнозируемым часам и фиксированным порогам, а не заменяет оперативную оценку условий на месте.
- Кэш локален для процесса и не переживает перезапуск; поиск безопасного окна кэш не использует.
- Dockerfile присутствует, однако существующая документация проекта сообщает, что локальная сборка Docker-образа не была проверена.
- Production-развёртывание и удалённый CI в текущей документации проекта не подтверждены.
