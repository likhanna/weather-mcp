# Weather MCP

Локальный MCP-сервер на Node.js и TypeScript. Он работает через STDIO и предоставляет инструменты для прогноза и оценки погодного риска, используя бесплатный [Open-Meteo API](https://open-meteo.com/) — API-ключ не нужен.

## Требования

- Node.js 20 или новее;
- npm.

## Установка и сборка

```powershell
cd C:\Users\boria\Desktop\AI-005\weather-mcp
npm install
npm run build
```

## Запуск

Для разработки:

```powershell
npm run dev
```

После сборки:

```powershell
npm start
```

Сервер ожидает MCP-клиента в STDIN. Не вводите JSON вручную в обычном терминале: проще использовать Inspector или подключить сервер к Codex. Статус и ошибки пишутся только в STDERR; STDOUT зарезервирован для MCP/JSON-RPC.

## Инструмент `get_weather`

Аргументы:

```json
{
  "city": "Dubai",
  "days": 3
}
```

- `city` — название города;
- `days` — целое число от 1 до 7.

Ответ содержит найденные город и страну, текущую и ощущаемую температуру, скорость ветра, текущие погодные условия, а также ежедневные минимальную и максимальную температуры. Если город не найден или Open-Meteo недоступен, инструмент возвращает MCP-ошибку с понятным сообщением.

## Инструмент `assess_weather_risk`

Пример аргументов:

```json
{
  "city": "Dubai, United Arab Emirates",
  "start_at": "2026-09-24T12:00",
  "work_type": "maintenance",
  "duration_hours": 2
}
```

`start_at` всегда задаётся **по московскому времени** в формате `YYYY-MM-DDTHH:mm`. Допустимые типы работ: `maintenance`, `installation`, `inspection`. Начало работ должно быть не раньше текущего момента, конец — не позднее пяти суток от него. Дробное число часов допускается.

Инструмент оценивает каждый затронутый час и выбирает самый высокий риск:

| Уровень | Вероятность осадков | Ветер | Температура | Рекомендация |
| --- | --- | --- | --- | --- |
| `HIGH` | от 70% | от 15 м/с | ниже −15 °C или выше 40 °C | `CANCEL` |
| `MEDIUM` | от 40% до менее 70% | от 10 до менее 15 м/с | ниже −5 °C или выше 32 °C | `REVIEW` |
| `LOW` | остальные случаи | остальные случаи | остальные случаи | `PROCEED` |

Ответ содержит найденную локацию и её часовой пояс, период в UTC, почасовые значения температуры, вероятности осадков и ветра, итоговый уровень, повлиявшие факторы, рекомендацию, источник Open-Meteo и время получения данных. При неоднозначном городе возвращается до пяти вариантов с просьбой уточнить название; город не выбирается автоматически. Для уточнения можно добавить страну или регион через запятую, например `Dubai, United Arab Emirates`. Внешние запросы ограничены пятью секундами, а одинаковый результат хранится только в памяти процесса до десяти минут. Пользовательские запросы и координаты не записываются на диск.

## Инструмент `find_safe_weather_window`

Инструмент ищет безопасные окна работ внутри будущего интервала. Время задаётся по Москве в формате `YYYY-MM-DDTHH:mm`; `search_start` не может быть раньше текущего момента, а `search_end` должен быть не позже пяти суток от него. Длительность — целое число от 1 до 8 часов.

```json
{
  "city": "Dubai, United Arab Emirates",
  "work_type": "maintenance",
  "search_start": "2026-09-28T08:00",
  "search_end": "2026-09-28T18:00",
  "duration_hours": 3
}
```

Кандидаты начинаются каждый полный час, начиная с первой часовой границы не раньше `search_start`. Окно допустимо, если полностью помещается в интервал; конец окна может совпасть с `search_end`. Прогноз загружается одним запросом после отдельного запроса геокодирования. Для каждого окна риск агрегируется существующими порогами: сначала сравнивается уровень (`LOW < MEDIUM < HIGH`), затем количество факторов (`factors.length`), затем более раннее время начала.

Успешный ответ `structuredContent` содержит `selected_window`, до трёх `alternatives`, `candidates_checked`, найденную `location`, `work_type`, `source` и UTC `fetched_at`. Каждый объект окна содержит московские `start_at`/`end_at`, длительность, уровень риска, рекомендацию и факторы. `candidates_checked` — число всех оценённых окон до ограничения числа альтернатив. Неоднозначный или неизвестный город не выбирается автоматически. Если подходящих окон нет, прогноз неполон или Open-Meteo недоступен, возвращается контролируемая ошибка без частичного результата.

Новый поиск не кэширует результаты: каждый успешный вызов получает свежий прогноз. Существующие инструменты `get_weather`, `assess_weather_risk` и `compare_weather_windows` сохраняют прежнее поведение.

## Инструмент `compare_weather_windows`

Инструмент сравнивает два будущих окна для одного города и одного типа работ. У каждого окна свои московские `start_at` и положительный `duration_hours`; оба периода проверяются до запроса погоды и должны завершиться в пределах пяти суток от текущего времени.

```json
{
  "city": "Dubai, United Arab Emirates",
  "work_type": "maintenance",
  "windows": [
    { "start_at": "2026-09-25T09:00", "duration_hours": 2 },
    { "start_at": "2026-09-26T09:00", "duration_hours": 3 }
  ]
}
```

Ответ содержит оба окна в исходном порядке с идентификаторами `window-1` и `window-2`, исходными временными параметрами и полной оценкой `assess_weather_risk`. Поле `selected_indices` содержит `[0]` или `[1]` для окна с меньшим уровнем риска (`LOW < MEDIUM < HIGH`). При равном `risk_level` возвращаются оба окна, `selected_indices` равен `[]`, а `tie` — `true`; инструмент не выбирает вариант по рекомендации, факторам или порядку. Краткое `explanation` описывает сравнение и рекомендацию. Если город не найден или неоднозначен, возвращается исходная ошибка геокодирования без победителя; ошибка погодного сервиса также не создаёт частичного сравнения.

## Проверки и локальный Docker

```powershell
npm run ci
docker build -t weather-mcp:local .
docker run --rm -i weather-mcp:local
```

Контейнер сохраняет STDIO для MCP и открывает `GET /health` только внутри контейнера на `127.0.0.1:8080`. Docker `HEALTHCHECK` обращается к этому пути. В обычном запуске через `npm start` HTTP listener выключен; для локальной проверки задайте `HEALTH_PORT=8080`. `npm run ci` — локальная команда сборки и тестов для этой демонстрации. Git-репозиторий и удалённый CI не требуются. Dockerfile подготовлен, но локальная сборка образа пока не проверена: пользователь выбрал продолжить без запущенного Docker Desktop.

План локального canary после отдельного разрешения: 20 последовательных MCP-запросов, каждый ответ соответствует схеме, ошибок сервера нет. Для отката локального контейнера остановите его и вернитесь к предыдущему образу или состоянию файлов. Production-деплой не предусмотрен.

```powershell

```

Inspector откроет локальный интерфейс в браузере. Нажмите **Connect**, откройте **Tools**, выберите `get_weather` и передайте:

```json
{

  "days": 3
}
```

```powershell

```

## Подключение к Codex

Ниже пример для пользовательского файла `~/.codex/config.toml`. Он приведён только как инструкция: проект не меняет этот файл автоматически.

```toml
[mcp_servers.weather]
command = "node"
args = ["C:/Users/YOUR_USERNAME/Desktop/AI-005/weather-mcp/dist/index.js"]
cwd = "C:/Users/YOUR_USERNAME/Desktop/AI-005/weather-mcp"
startup_timeout_sec = 20
tool_timeout_sec = 20
```

Замените `YOUR_USERNAME` на имя пользователя Windows, сохраните конфигурацию и перезапустите Codex. Либо в Codex Desktop откройте **Settings → MCP servers → Add server**, выберите **STDIO** и укажите те же команду и аргумент.

Подробнее о настройке STDIO-серверов: [официальная документация Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
