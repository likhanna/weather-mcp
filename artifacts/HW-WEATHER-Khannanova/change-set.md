# Change set — HW-WEATHER-Khannanova

## Исходная ветка и ревизия

`weather-mcp` в предоставленной рабочей копии не является Git-репозиторием (`.git` отсутствует); ветка и исходный commit SHA определить невозможно. В README прямо указано, что локальной демонстрации Git не требуется.

## Реализация

Добавлен MCP tool `find_safe_weather_window`: он валидирует московский поисковый интервал и длительность, создаёт уникальные полные часовые старты, геокодирует город с отказом при неоднозначности, загружает один общий прогноз и ранжирует локальные оценки через существующий `assessRisk`. Ответ включает победителя, до трёх альтернатив, число оценённых кандидатов, локацию, тип работ, источник и время получения прогноза. Новый поиск не использует кэш. Существующие обработчики и пороги риска не менялись.

## Изменённые файлы

- `weather-mcp/src/time.ts` — независимые функции парсинга поиска, генерации окон и форматирования московского времени.
- `weather-mcp/src/weather-windows.ts` — детерминированная сортировка по уровню риска, числу факторов и UTC start.
- `weather-mcp/src/open-meteo.ts` — новый метод поиска; один forecast request и проверка полного набора часов всех окон.
- `weather-mcp/src/index.ts` — Zod-схема, MCP-регистрация и обработка ошибок нового tool.
- `weather-mcp/test/find-safe-weather-window.test.mjs` — unit, service, MCP и generative проверки.
- `weather-mcp/test/compare-weather-windows.test.mjs`, `mcp-health.test.mjs` — ожидания списка инструментов обновлены с 3 до 4; поведение прежних tools не менялось.
- `weather-mcp/README.md` — описание нового инструмента, семантики времени, сортировки, ответа и отказов.
- `artifacts/HW-WEATHER-Khannanova/verification.md` — фактические результаты CI и ручных MCP-вызовов.

## Критерии приёмки

- Zod принимает только целую длительность 1–8 и строгий набор полей.
- Времена преобразуются Москва → UTC; поиск ограничен `now` и `now+5d`, кандидаты идут по полным часам и помещаются в границы.
- Все допустимые окна оцениваются одним forecast response; неполный прогноз и сетевые ошибки не дают partial result.
- Пороговая логика переиспользует `assessRisk`; порядок детерминирован `(risk, factors.length, start)`.
- MCP-ответ стабилен; старые три tool contracts сохранены.
- README обновлён; CI и живые вызовы Inspector завершились по данным в verification.
