# Промпты агентов

## Состав

- `01_прием_задачи.md`: превращает исходную карточку в спецификацию и вопросы.
- `02_планирование.md`: создаёт проверяемый технический план.
- `02a_карта_репозитория.md`: исследует структуру проекта и создаёт `repository-map.md`.
- `02b_анализ_зависимостей.md`: исследует пакеты, среды и внешние сервисы и создаёт `dependency-map.md`.
- `03_реализация.md`: вносит минимальные изменения и запускает проверки.
- `04_независимая_проверка.md`: ищет подтверждённые дефекты в реализации.
- `05_релиз.md`: готовит безопасный merge, canary, deploy и rollback.
- `06_документация.md`: создаёт runbook и итоговую документацию.
- `07_проверка_процесса.md`: проверяет весь workflow на системные слабости.
- `08_презентация_результата.md`: собирает проверенную учебную PPTX по артефактам конкретной задачи.

## Быстрый запуск

Открой папку `C:\Users\boria\Desktop\AI-005` как проект в Codex и создай новую задачу с сообщением:

```text
Обработай задачу по процессу из Agent.md.

Источник задачи: <вставь текст карточки или ссылку Trello>.

Сначала создай постоянный task_key и отдельную папку artifacts/<task_key>/. Затем выполни только этап приёма и анализа. Создай task.json, task-spec.json и questions.md. Сообщи мне task_key. Не переходи к реализации, пока я не отвечу на вопросы и не одобрю план.
```

Codex автоматически читает `AGENTS.md`, а тот направляет его к `Agent.md`. Промпты ролей оркестратор загружает по мере перехода между этапами.

## Параллельный анализ большого проекта

После приёма задачи можно запустить два независимых субагента:

```text
Продолжи задачу <task_key>.

Запусти параллельно два субагента:
1. Repo Mapper читает agents/02a_карта_репозитория.md и создаёт repository-map.md.
2. Dependency Analyst читает agents/02b_анализ_зависимостей.md и создаёт dependency-map.md.

Оба работают только на чтение и пишут только в artifacts/<task_key>/.
Дождись обоих результатов, сравни их и создай context-package.md.
К планированию и реализации не переходи.
```

Если субагенты недоступны, оркестратор выполняет обе роли последовательно и честно сообщает об этом.

## Запуск отдельной роли

Чтобы выполнить только один этап, используй сообщение:

```text
Для задачи с task_key `<указать ключ>` прочитай agents/04_независимая_проверка.md и выполни только роль критика. Используй файлы только из artifacts/<task_key>/, текущий diff и реальные результаты тестов. Не выполняй merge и deploy.
```

## Работа без подключённых MCP

Если Trello, GitHub, Kubernetes или Confluence MCP не подключены, передай данные файлами или текстом. Агент подготовит локальные артефакты, но не должен утверждать, что изменил внешнюю систему.

## Разделение нескольких задач

Каждая задача хранится отдельно:

```text
artifacts/
├── index.json
├── ai-1423-payment-timeout/
│   ├── task.json
│   ├── workflow-status.json
│   ├── task-spec.json
│   └── ...
└── trello-67ab21-weather-alerts/
    ├── task.json
    ├── workflow-status.json
    ├── task-spec.json
    └── ...
```

При продолжении работы всегда называй `task_key`. Если его не указать при нескольких активных задачах, оркестратор должен остановиться и попросить выбрать задачу.
